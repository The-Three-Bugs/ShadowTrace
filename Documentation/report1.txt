3. DETAILED ARCHITECTURE & APP WORKFLOW (HOW IT WORKS)
--------------------------------------------------------------------------------

A. Investigation Lifecycle & Management
- Containerization: Every incident begins with an Investigation. An investigation holds metadata (`id`, `investigation_uid`, `title`, `description`, `status`, `created_at`, `updated_at`).
- UID Generation: Automatically generated unique identifier format (e.g., `INV-20261117-A1B2C3`).
- Search & Filtering: Users can search by title or UID and filter by status (`Open`, `In Progress`, `Completed`, `Archived`). Archiving preserves historical evidence without permanent deletion.

B. Secure Evidence Upload Workflow
- Association: Users select an active investigation and trigger a CSV evidence upload.
- Validation: The Flask backend (`POST /api/investigations/<id>/evidence`) verifies that the investigation exists, checks the `.csv` extension, confirms the file is non-empty, and enforces size limits.
- SHA-256 Hashing: Before any parsing or normalization, the system reads the original file stream bytes and computes a cryptographic SHA-256 checksum.
- Duplicate Detection: Checks existing records in SQLite to prevent duplicate uploads of identical evidence files (`409 Conflict`).
- Secure Storage: Generates a safe internal filename (`uuid_originalfilename.csv`) and stores the file in `instance/evidence/`, completely outside the public frontend directory.
- Metadata Persistence: Records evidence metadata (`investigation_id`, `original_filename`, `stored_filename`, `file_size`, `sha256_hash`, `upload_timestamp`, `processing_status`) in SQLite.

C. Cryptographic Integrity Verification Workflow
- Inspection: When viewing evidence details (`GET /api/evidence/<id>` or listing evidence for an investigation), the system locates the stored file on disk.
- Recalculation & Comparison: The system recalculates the SHA-256 hash of the stored file bytes and compares it with the recorded hash.
- Verification Statuses:
  1. `Integrity Verified`: Hash matches the recorded reference.
  2. `Integrity Mismatch`: File bytes on disk have been altered or tampered with.
  3. `Verification Failed (File Missing)`: The underlying evidence file is missing from storage.

D. API & Frontend Integration
- All interactions communicate via REST API endpoints (`/api/investigations`, `/api/investigations/<id>`, `/api/investigations/<id>/evidence`, `/api/evidence/<id>`).
- The Vanilla JavaScript frontend (`static/js/app.js`) renders responsive tables, modals, badges, and notification toasts while strictly respecting existing design conventions and CSS frameworks.
- Automated tests (`python -m unittest tests/test_shadowtrace.py`) verify the complete lifecycle successfully.
